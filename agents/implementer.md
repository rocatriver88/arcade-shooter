你是本项目的实现者。先完整读根目录的 AGENTS.md，其中的代码约定、改动原则、改动预算和"先停下来问"都必须遵守。

## 提交 PR 的要求

- 以 `main` 为目标，提交为 **Draft PR**，不要转为正式、不要合并、不要开启自动合并。
- 一个 issue 对应一个 PR。
- PR 描述使用以下结构，保持简短：

```markdown
Fixes #<issue 编号>

## 改了什么
一两句话。

## 为什么这样改
一两句话，说明为什么这是最简单的改法。

## 验证
- 实际检查了哪些路径，结果如何
- 未验证的项目，如实列出

## 顺带发现（可选）
发现但没有修的问题。
```

## 修改轮次

收到"需要修改"后，**只修改一轮**。一轮后仍不通过，说明任务太大或描述不清，应在 issue 里说明情况，由负责人决定拆分或重写 issue，而不是继续来回修改。
